Singly Linked List Memory Architecture

The Linked List is the Sole Owner of the medicine records. Nodes are dynamically allocated on the heap via new Node.

// Core Node & Append Implementation in C++ (modules/InventoryList.cpp) struct Node { Medicine data; // Record payload Node* next; // Heap pointer to next element }; void InventoryList::addMedicine(const Medicine& m) { Node* newNode = new Node; newNode->data = m; newNode->next = nullptr; if (head == nullptr) { head = newNode; } else { Node* current = head; while (current->next != nullptr) current = current->next; current->next = newNode; } }

Teacher Viva & Defense Question Bank
Q1. Why are you using 4 different data structures instead of just one?
Each structure serves a distinct optimal role:
1. Singly Linked List: Stores dynamic master records without array resizing.
2. Hash Table: Provides O(1) instant search and updates by Medicine ID.
3. Binary Search Tree: Provides O(log n) chronological sorting and expiry queries (in-order traversal).
4. Circular Queue: Enforces fair First-In, First-Out (FIFO) processing for supplier restock orders without shifting array items.
Q2. What is the Hash Function and how are collisions handled?
The hash function sums the ASCII integer values of all characters in the Medicine ID string, then takes modulo 11:
int index = sum(id[i]) % 11;
Collisions are resolved via Separate Chaining: each bucket is the head of a linked list. For instance, MED101 and MED110 both hash to Bucket 8 and form a linked list chain.
Q3. Why is the Queue implemented as Circular rather than a normal array?
In a standard linear array queue, dequeuing leaves dead empty slots at the front. Moving elements to index 0 requires O(n) shifts. A circular queue wraps around using modulo arithmetic:
rear = (rear + 1) % MAX_REQUESTS;
This guarantees both Enqueue and Dequeue remain strictly O(1)!
Q4. How do you prevent memory leaks when deleting a medicine?
We synchronize deletion across all three index structures:
1. Unlink from BST and remove the date node if empty.
2. Unlink the HashNode from its bucket chain and delete it.
3. Unlink the Node from the master Linked List and delete current to deallocate heap memory.
